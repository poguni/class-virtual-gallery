- 이 문서의 성격: Phase 1~7(v8까지)의 내용에 Phase 8(전시실 테마·소품), 방 이동 멈춤 수정, 교사용 "처음 화면으로" 버튼, Phase 9(로비 리뉴얼)를 더한 **전체 스냅샷**입니다. 새 대화창에서는 이 문서(v9) 하나만 참고하면 되고, 다음 작업 후 `v10`으로 갱신하는 방식을 유지해 주세요.

## 0. 새 대화창에서 작업을 이어가는 방법

1. 저장소를 내려받아 그 폴더에서 작업합니다: `git clone https://github.com/poguni/class-virtual-gallery.git`
2. 이 문서(`docs/Development_Guide_v9.md` 또는 `.html`)를 먼저 읽게 합니다.
3. 요청 예시:

> "docs/Development_Guide_v9.md를 참고해서 이어서 개발해줘. 다음 작업은 ◯◯이야."

- 코드는 **여러 파일로 나뉘어 있으므로**(4.2절) 고칠 기능에 해당하는 파일만 보면 됩니다.
- DB를 바꾸는 작업이면 `supabase/migrations/`에 SQL을 남기고, 되돌리기 SQL도 `supabase/rollback/`에 함께 둡니다(12절의 절차 참고).
- 3D 화면을 바꾸는 작업이면 **조명 개수를 늘리지 않는 것**이 원칙입니다(8절·10절). 조명을 새로 만들면 방 이동 때 멈춤이 다시 생길 수 있습니다.

## 2. 목표 및 배경

- 미술 시간에 완성한 작품을 교실 벽에만 걸어두지 않고, **언제 어디서나 들어가 볼 수 있는 전시관**으로 만들어 주기 위해 시작했습니다.
- 교사는 사진 파일을 한 번에 올리기만 하면 되고(파일명으로 이름·제목 자동 입력, 전시실 자동 배정), 학생·학부모는 **QR코드 하나로** 바로 입장합니다.
- 감상 활동(좋아요·댓글)을 교사가 **감상 결과 리포트**로 내려받아 평가 자료로 활용할 수 있습니다.
- Phase 7은 여러 선생님이 함께 쓰기 위한 **보안·교사별 전시 분리**가 목표였습니다.
- Phase 8~9는 **"진짜 미술관에 온 느낌"**이 목표였습니다. 전시실마다 주제에 맞는 분위기(테마·소품)를 고를 수 있게 하고, 검은 배경이 보이던 로비를 밝은 현대 미술관 로비로 바꿨습니다. 휴대폰에서 방을 옮길 때 끊기던 문제도 함께 해결했습니다.

## 3. 주요 기능

**감상(학생·학부모)**
- 로그인 없이 입장, QR코드·공유 링크(`?t=교사코드`)로 해당 교사의 현재 전시 관람
- 1인칭 이동: PC는 WASD + 방향키 + 마우스 클릭, 모바일은 자체 구현 조이스틱 + 드래그 + 탭
- 로비 → A동 전시실들 → 연결 통로 → B동 전시실들 → 로비로 돌아오는 순환(ㅁ자) 동선
- **[Phase 9] 밝은 화이트 로비**: 통유리벽 너머 낮 정원(하늘·잔디·돌길·나무), 테라초 바닥, 천장 선 조명, 창가 벤치·화분
- **[Phase 8] 전시실 테마 6종**: 클래식(기본)·화이트 큐브·숲속 정원·바닷속·밤하늘·크레파스 놀이터. 테마마다 벽·바닥·천장 무늬, 액자, 강조색, 소품이 달라짐
- 소품·벤치·화분에는 부딪힘 처리가 되어 있어 통과하지 않음
- 작품 확대 보기, 좋아요(방문자 키로 중복 방지), 댓글(이름 10자·내용 80자)
- 스마트폰 뒤로 가기 시 열린 창만 한 단계씩 닫힘

**관리(교사)**
- 회원가입 → **관리자 승인** 후 사용
- 새 전시 만들기: 폴더/여러 장 업로드, 파일명(`번호_이름_제목.jpg`) 자동 해석, 방 자동 배정(방당 8점 기준 균등 분배), 진열 순서(이름순·랜덤·직접)
- 기존 전시 관리: 정보 수정, 작품 수정·삭제·순서 변경, 작품 추가, 전시 삭제
- **[Phase 8] 전시실별 테마 선택 + 색 견본 + 소품 표시 켜기/끄기** (바꾸면 바로 저장)
- **현재 전시장 설정**: 교사마다 하나의 전시를 방문자에게 공개(`is_active`)
- 관리자 화면 상단의 **"우리 반 링크" 표시·복사** 버튼
- 댓글 숨김/복원, 감상 결과 리포트(오프라인 HTML 파일) 다운로드
- 관리자 전용 **교사 승인 탭**
- 시작·로그인 화면 "미술관 입장권" 디자인
- 전시장 안 오른쪽 위 **"↩ 처음 화면으로"**(로그아웃 없이 업로드 관리자·QR 화면으로 복귀)와 **로그아웃** 버튼

## 4. 기술 스택 및 아키텍처

### 4.1 구성 요소

| 영역 | 사용 기술 | 선택 이유 |
|---|---|---|
| 화면·3D | Vanilla JS + Three.js r128 (cdnjs) | 빌드 없이 파일만 올리면 동작, 교사가 직접 관리하기 쉬움 |
| 질감·무늬 | Canvas 2D로 그린 텍스처 | 이미지 파일을 따로 두지 않아 저장소가 가볍고, 무늬를 코드로 조정 가능 |
| 백엔드 | Supabase (Auth · Postgres · Storage) | 서버 없이 로그인·DB·이미지 저장을 한 번에 해결, RLS로 권한 제어 |
| QR | qrcodejs 1.0.0 (cdnjs) | 접속 주소를 그 자리에서 QR로 그림 |
| 배포 | GitHub Pages (`main` 브랜치 루트) | 무료, push만 하면 1~2분 안에 자동 배포 |

### 4.2 파일 구조

```
(저장소 루트)
├── index.html              ← 화면 구조(HTML)만. CSS·JS를 불러옴
├── css/style.css           ← 모든 화면 디자인
├── js/                     ← 아래 순서대로 불러옴 (순서 변경 금지)
│   ├── auth.js             ← Supabase 연결, 로그인, 교사 승인 확인, QR코드
│   ├── demo-data.js        ← 데모(더미) 작품
│   ├── gallery-data.js     ← 전시·좋아요·댓글 불러오기 (전시실 theme·show_props 포함)
│   ├── themes.js           ← [Phase 8] 전시실 테마 정의·재질·캔버스 무늬·보조광
│   ├── props.js            ← [Phase 8] 테마별 소품, 소품 부딪힘 영역(PROP_OBSTACLES)
│   ├── scene.js            ← 3D 전시장 (로비·복도·전시실·조명 풀·작품 배치)
│   ├── lobby.js            ← [Phase 9] 로비 유리벽·바깥 정원·천장 선 조명·벤치와 화분
│   ├── controls.js         ← 이동, 벽·소품 충돌, 모바일 조이스틱
│   ├── viewer.js           ← 화면 갱신 루프, 시작 화면, 작품 창, 좋아요·댓글, 교사 버튼
│   ├── admin-upload.js     ← 새 전시 만들기, 교사 승인 탭
│   ├── admin-manage.js     ← 기존 전시 관리, 전시실 테마 설정, 작품 추가
│   └── report.js           ← 감상 결과 리포트
├── assets/                 ← 시작·로그인 화면 배경 (PC/모바일)
├── supabase/
│   ├── migrations/         ← 적용한 DB 변경 SQL (기록용)
│   └── rollback/           ← 되돌리기 SQL
├── docs/                   ← 개발 가이드(이 문서)
└── README.md               ← 배포 가이드
```

- JS 파일은 모듈(`import`)이 아닌 **일반 `<script>`**로 불러와 전역 변수를 함께 씁니다. `themes.js`·`props.js`는 `scene.js`가 쓰므로 그 앞에, `lobby.js`는 `scene.js`의 `LOBBY`·재질을 쓰므로 **바로 뒤에** 둡니다.
- `?v=`는 브라우저 캐시 방지용입니다. 현재 값 예: `scene.js?v=20261024i`, `lobby.js?v=20261024e`, `viewer.js?v=20261024g`, `style.css?v=20261024g`. 하루에 여러 번 배포하므로 날짜 뒤에 알파벳을 붙여 올립니다.
- 코드 규모: JS 12개 약 3,900줄, CSS 540줄, HTML 335줄.

### 4.3 DB 구조 (Supabase 프로젝트 `xloetjawdupadtfquxka`)

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `teachers` | `user_id`, `email`, `status`(pending/approved/rejected), `is_admin`, `share_code`, `approved_at` | 회원가입 시 트리거가 `pending`으로 자동 등록 |
| `exhibitions` | `id`, `title`, `grade`, `class`, `created_at`, `owner_id`, `is_active` | 교사별 현재 전시는 하나(부분 유니크 인덱스) |
| `rooms` | `id`, `exhibition_id`, `room_number`, `name`, **`theme`**, **`show_props`** | Phase 8: `theme` 기본 `classic`, 6종만 허용(체크 제약). `show_props` 기본 켬 |
| `artworks` | `id`, `room_id`, `student_name`, `title`, `image_url`, `created_at` | 진열 순서 = `created_at` 순 |
| `likes` | `artwork_id`, `visitor_key`, `created_at` | `(artwork_id, visitor_key)` 유니크 |
| `comments` | `artwork_id`, `nickname`, `content`, `is_hidden`, `created_at` | 이름 1~10자, 내용 1~80자 DB 제약 |

- `rooms.theme` 허용 값: `classic`, `whitecube`, `forest`, `ocean`, `night`, `crayon` — `js/themes.js`의 `ROOM_THEMES` 키와 **같아야 합니다.** 테마를 추가하려면 두 곳을 함께 고칩니다.
- Storage 버킷 `artwork-images`(public): 경로 `전시ID/전시실ID/파일명`, 10MB 이하·jpeg/png/webp/gif만 허용.
- DB 함수(RPC): `get_active_exhibition(p_code)`, `like_counts(p_artwork_ids)`, `set_active_exhibition(p_ex)`.
- 정책 판단용 헬퍼는 API로 노출되지 않는 `private` 스키마: `is_approved_teacher`, `is_admin`, `can_manage_exhibition`, `is_public_exhibition`, `room_exhibition`, `artwork_exhibition`, `can_manage_storage_path`, `request_visitor_key`.

### 4.4 권한 모델 (RLS)

| 대상 | 방문자(비로그인) | 승인 대기 교사 | 승인 교사 | 관리자 |
|---|---|---|---|---|
| 현재 전시(`is_active`) 조회 | ✅ | ✅ | ✅ | ✅ |
| 지난 전시 조회 | ❌ | ❌ | 내 것만 | 내 것만 |
| 전시·전시실(테마 포함)·작품·이미지 생성/수정/삭제 | ❌ | ❌ | 내 것만 | 내 것만 |
| 댓글 등록 | 공개 전시에 | 공개 전시에 | ✅ | ✅ |
| 숨긴 댓글 조회·댓글 숨김/삭제 | ❌ | ❌ | 내 전시만 | 내 전시만 |
| 좋아요 조회·취소 | 내 방문자 키만 | 〃 | 내 전시 전체 조회 | 〃 |
| 교사 승인/거절 | ❌ | ❌ | ❌ | ✅ |

- 방문자 키는 브라우저 `localStorage`에 만들고, 모든 요청에 **`x-visitor-key` 헤더**로 보냅니다.
- 관리자는 승인만 담당하며 **다른 교사의 전시는 관리자도 볼 수 없습니다.**
- Phase 8의 테마 컬럼은 기존 "내 전시의 전시실만 수정" 정책이 그대로 적용되어 **정책 변경이 없었습니다.**

## 6. 전체 공간(동선) 구조

```
          (바깥 정원: 하늘·잔디·돌길·나무 띠)
                 ═══════════════   ← [Phase 9] 통유리벽 + 유리문
                 │ 벤치    벤치 │  화분은 양 모서리
                 │     로비      │  (환영 사인: 실제 전시 학년/반 표시)
                 │  A동문   B동문 │
                 └──┬─────────┬──┘
                    │         │
              [A동 복도]   [B동 복도]
                    │         │
              [제1전시실]  [제N전시실]  (B동은 방 번호를 뒤집어서 지음)
                    │         │
                    …         …
                    │         │
              [제k전시실]  [제k+1전시실]
                    │         │
                    └────┬────┘
                   [연결 통로(가로)]  ← 두 동의 가장 안쪽 끝을 이어붙임
```

- 전시실의 앞쪽 절반은 A동(나가는 길), 뒤쪽 절반은 B동(돌아오는 길)에 배정합니다. B동은 방 순서를 뒤집어 지어서, 연결 통로를 지나 로비 쪽으로 걸어오면 번호 순서대로 마주칩니다.
- 로비 입구 쪽(`LOBBY.maxZ`)은 예전에는 벽 없이 열려 있어 검은 화면이 보였습니다. Phase 9에서 이 자리에 유리벽을 세웠습니다(걸어 나갈 수는 없음).
- 예: 작품 22점 → 방 3개(8/7/7) → A동에 1·2관, B동에 3관.

## 8. 주요 의사결정과 이유

| 결정 | 이유 |
|---|---|
| 회원가입 즉시 교사 → **관리자 승인제** | 가입이 열려 있어 학생이 아무 이메일로 가입해 전시 전체를 지울 수 있었음 |
| 전시에 `owner_id`, 교사별 `is_active` 하나, 공유 링크는 교사 코드(`?t=`) | 다른 교사의 전시 분리 + 현재 전시를 바꿔도 인쇄한 QR을 계속 사용 |
| 정책 헬퍼를 `private` 스키마에, 좋아요는 헤더 + `like_counts()` | 공격 면 축소, 비로그인 방문자 구분 |
| 파일 분리는 모듈화 없이 "잘라서 옮기기" | 빌드 도구 없이 GitHub Pages 배포 방식을 그대로 유지 |
| **[8] 테마는 전시실 단위로 고르게** | 한 전시 안에서도 방마다 주제(예: 숲 그림 방, 바다 그림 방)를 달리할 수 있게 |
| **[8] 테마를 4단계(틀 → 테마 → 소품 → DB 연결)로 나눠 진행** | 단계마다 "클래식은 변경 전과 픽셀 단위로 같다"를 확인해 기존 전시가 바뀌지 않음을 보장. DB 연결은 맨 마지막에 해 그전까지는 운영 데이터에 영향 없음 |
| **[8] 무늬는 이미지 파일 대신 캔버스로 그림** | 저장소에 이미지 파일을 늘리지 않고, 색·밀도를 코드에서 바로 조정 |
| **[8] 기존 전시실은 모두 `classic` 기본값** | 마이그레이션만으로는 어떤 전시도 모습이 바뀌지 않게. 교사가 직접 고를 때만 바뀜 |
| **[8] 소품은 감상 공간·통로를 비우는 자리에만, 부딪힘 처리** | 작품 앞을 가리거나 길을 막지 않게. 통과되는 소품은 어색함 |
| **[멈춤] 조명을 지웠다 만들지 않고 "조명 풀"에서 옮기기** | three.js는 조명 개수가 바뀌면 모든 재질의 셰이더를 다시 컴파일함 → 휴대폰에서 1~3초 멈춤. 개수를 고정하면 다시 컴파일이 일어나지 않음 |
| **[멈춤] 로드 직후 `renderer.compile`** | 처음 보는 방의 재질도 미리 준비해 첫 방문 때 멈추지 않게 |
| **"처음 화면으로"는 새로고침으로 구현** | 로그인 세션이 유지되므로 새로고침만으로 시작 화면에 돌아옴. 3D 장면을 정리하는 별도 코드가 필요 없고 상태가 꼬일 일이 없음 |
| **[9] 로비 뒤쪽은 "유리벽 + 바깥 정원", 톤은 "밝은 화이트"** (사용자 선택) | 검은 배경을 가리면서 현대 미술관 분위기. 막힌 벽보다 개방감이 있음 |
| **[9] 로비 밝기는 조명 추가 대신 발광 재질로** | 조명 수가 늘면 멈춤이 다시 생기고 휴대폰 부담도 커짐 |
| **[9] 바깥 풍경은 조명 영향 없는 재질 + 안개 끔** | 실내 조명·안개 때문에 하늘이 회색으로 바래지 않게, 계산도 가벼움 |
| **[9] 나무 띠를 평면 대신 열린 반원통으로** | 평면은 비스듬히 보면 끝이 드러남. 반원통의 양 끝은 로비 옆벽 뒤에 숨음 |
| **[9] 로비 파일(`lobby.js`)을 따로 분리** | `scene.js`가 이미 커서, 로비 장식만 따로 고치기 쉽게 |

## 9. 문제 해결 기록 (누적)

### 9.1 Phase 8~9에서 해결한 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 휴대폰에서 다음 전시실로 넘어갈 때 1~2초(측정 최대 2.95초) 멈춤 | 가까운 방 조명만 씬에 넣었다 뺐다 하면서 조명 개수가 바뀌어 셰이더 재컴파일(방마다 새 프로그램 3개) | 조명 풀(개수 고정, 위치만 이동) + 로드 직후 미리 컴파일 → 방 이동 1~3ms, 새 프로그램 0개 |
| 교사가 전시장을 본 뒤 설정을 바꾸려면 로그아웃 → 재로그인 필요 | 전시장 안에서 시작 화면으로 돌아가는 길이 없음 | "↩ 처음 화면으로" 버튼(새로고침, 세션 유지) |
| 로비 뒤쪽에 검은 배경이 보임 | 로비 입구 쪽이 벽 없이 열려 있었음 | 통유리벽 + 바깥 정원 |
| 나무 띠의 끝이 비스듬한 각도에서 보임 | 평평한 판 하나로 그림, 넓혀도 해결 안 됨 | 열린 반원통으로 교체, 캔버스 비율(2048 폭)과 나무 개수를 폭에 맞춰 조정 |
| 흰 벽에 간판 스포트라이트가 하얗게 타서 얼룩 | 밝은 벽에 강한 조명 | 간판 조명 세기 1.6→0.6 / 1.4→0.8, 가장자리를 부드럽게(penumbra 0.8) |
| 흰 벽이 연보라색으로 보임 | 푸른 환경광이 흰 벽에 그대로 드러남 | 벽 바탕색을 살짝 낮추고 따뜻한 발광 추가 |
| 화분 잎이 회녹색으로 바래 보임 | sRGB 출력에서 색이 밝고 연해짐 | 더 진하고 채도 높은 녹색 + 발광 |
| 밝은 테마의 벽이 어둡게 보임 | 작품 스포트라이트만으로는 방 전체가 어두움 | 테마별 방 가운데 보조광(그림자 없음), 역시 조명 풀에 포함 |

### 9.2 Phase 7에서 해결한 문제

| 증상 | 원인 | 해결 |

## 10. 보안·성능 고려사항

**보안**
- **anon key**는 공개되어도 되는 키이며 보호는 RLS가 담당합니다. Service Role Key는 절대 코드에 넣지 않습니다.
- **Supabase Auth**: 회원가입 허용(승인제), 이메일 인증 켬, Google 로그인 꺼짐(버튼 숨김).
- **보안 진단 현황**: 방문자용으로 의도적으로 공개한 SECURITY DEFINER 함수 경고 2건, 유출 비밀번호 차단 꺼짐 경고 1건.
- Phase 8의 `rooms.theme`은 체크 제약으로 6개 값만 허용 — 잘못된 값이 저장되지 않음. 앱도 모르는 키는 클래식으로 처리.

**성능 (3D)**
- **조명 개수는 처음 한 번 정한 뒤 바꾸지 않습니다.** 조명을 추가·삭제하거나 그림자 켜기/끄기를 바꾸면 셰이더 재컴파일로 멈춤이 생깁니다. 새 장식은 발광 재질이나 `MeshBasicMaterial`로 밝기를 냅니다.
- 그림자는 현재 방 작품 조명만(그림자맵 768). 가까운 방(2칸 이내)만 조명을 배치.
- 테마 재질은 테마별로 한 번만 만들어 재사용. 무늬 텍스처는 256~512px 캔버스(로비 하늘 1024×512, 나무 띠 2048×384).
- 충돌 검사는 프레임당 사각형 십여 개 × 4점 비교로 부담이 거의 없음.

## 12. 배포

- **방식**: GitHub Pages, `main` / `(root)`. push 후 1~2분 안에 자동 반영.
- **주소**: https://poguni.github.io/class-virtual-gallery/ (교사별 링크: `…/?t=교사코드`)

- **작업 방식**: 기능마다 `feature/...` 브랜치에서 작업 → 검증 → 사용자 요청 시 커밋 → `main`에 합쳐 push → 배포 사이트 확인 → 브랜치 삭제.
- **DB 변경 절차**:
  1. `supabase/migrations/`에 SQL + `supabase/rollback/`에 되돌리기 SQL
  2. 오류로 끝나게 바꿔 **시험 실행** → 아무것도 남지 않았는지 확인
  3. 수업이 없는 시간에 **SQL 적용과 앱 push를 한 번에**
  4. 보안 진단 재실행 + 배포 사이트 확인
- **되돌리기**
  - 테마: `supabase/rollback/20261024_room_themes_rollback.sql`(컬럼 삭제) + 앱을 `65fdcbf` 이전으로. 앱만 되돌려도 컬럼은 무시되므로 DB는 그대로 둬도 됨
  - 교사 승인제: `supabase/rollback/20261023_teacher_approval_and_ownership_rollback.sql`
  - 로비 리뉴얼만 되돌리기: `git revert 103e0e8`

## 13. 알려진 한계

- **교사마다 방문자에게 공개되는 전시는 하나**입니다.
- **현재 전시는 공개용이라**, API를 직접 다루는 사람은 다른 반의 현재 전시를 조회할 수 있습니다(지난 전시는 불가).
- **좋아요 중복 방지는 브라우저 기준**입니다.
- **댓글 부적절어 필터가 없습니다**(사용자 결정으로 보류).
- **진열 순서를 `created_at`에 의존**합니다.
- **JS 파일이 전역 변수를 공유**하므로 불러오는 순서에 의존합니다.
- **조명 개수를 늘리는 장식은 넣기 어렵습니다.** 새 장식의 밝기는 발광 재질로만 표현해야 멈춤이 생기지 않습니다.
- **테마를 추가하려면 코드(`themes.js`, `props.js`)와 DB 체크 제약을 함께 바꿔야** 합니다.
- **로비 유리문은 장식**입니다. 열리거나 밖으로 나갈 수 없습니다. 바깥 정원은 그림이라 가까이서 보면 평면적입니다.
- **작품 사진이 큰 편(약 1500×2000)**이라, 휴대폰에서 처음 들어갈 때 이미지를 받는 동안 잠깐 버벅일 수 있습니다(방 이동 멈춤과는 별개).
- 발표용 테스트 계정의 복사본 전시는 원본과 이미지 파일을 공유합니다.
- 로그인 후 처음 들어올 때 한 번 새로고침될 수 있습니다. `favicon.ico`가 없어 콘솔에 404가 하나 남습니다.
