작성일: 2026-10-24
버전: v9
이전 버전: v8 (docs/Development_Guide_v8.md, 2026-10-24)
이 문서의 성격: Phase 1~7(v8까지)의 내용에 Phase 8(전시실 테마·소품), 방 이동 멈춤 수정, 교사용 "처음 화면으로" 버튼, Phase 9(로비 리뉴얼)를 더한 전체 스냅샷입니다. 새 대화창에서는 이 문서(v9) 하나만 참고하면 되고, 다음 작업 후 v10으로 갱신하는 방식을 유지해 주세요.

0. 새 대화창에서 작업을 이어가는 방법

  1. 저장소를 내려받아 그 폴더에서 작업합니다: git clone https://github.com/poguni/class-virtual-gallery.git
  2. 이 문서(docs/Development_Guide_v9.md 또는 .html)를 먼저 읽게 합니다.
  3. 요청 예시:
"docs/Development_Guide_v9.md를 참고해서 이어서 개발해줘. 다음 작업은 ◯◯이야."
  • 코드는 여러 파일로 나뉘어 있으므로(4.2절) 고칠 기능에 해당하는 파일만 보면 됩니다.
  • DB를 바꾸는 작업이면 supabase/migrations/에 SQL을 남기고, 되돌리기 SQL도 supabase/rollback/에 함께 둡니다(12절의 절차 참고).
  • 3D 화면을 바꾸는 작업이면 조명 개수를 늘리지 않는 것이 원칙입니다(8절·10절). 조명을 새로 만들면 방 이동 때 멈춤이 다시 생길 수 있습니다.

1. 개요

항목내용
앱 이름우리 반 가상 미술관 (Class Virtual Gallery)
한 줄 소개학생 작품 사진을 올리면 3D 가상 미술관이 자동으로 만들어지고, 학생·학부모가 접속해 감상하며 좋아요·댓글을 남기는 초등 학급용 웹 앱
대상 사용자초등 교사(전시 생성·관리), 학생·학부모(로그인 없이 감상)
배포 주소https://poguni.github.io/class-virtual-gallery/
저장소https://github.com/poguni/class-virtual-gallery
개발 기간2026-07 (Phase 1~6) → 2026-08-29 (전시장 교체 기능) → 2026-10-23~24 (Phase 7~9)

2. 목표 및 배경

  • 미술 시간에 완성한 작품을 교실 벽에만 걸어두지 않고, 언제 어디서나 들어가 볼 수 있는 전시관으로 만들어 주기 위해 시작했습니다.
  • 교사는 사진 파일을 한 번에 올리기만 하면 되고(파일명으로 이름·제목 자동 입력, 전시실 자동 배정), 학생·학부모는 QR코드 하나로 바로 입장합니다.
  • 감상 활동(좋아요·댓글)을 교사가 감상 결과 리포트로 내려받아 평가 자료로 활용할 수 있습니다.
  • Phase 7은 여러 선생님이 함께 쓰기 위한 보안·교사별 전시 분리가 목표였습니다.
  • Phase 8~9는 "진짜 미술관에 온 느낌"이 목표였습니다. 전시실마다 주제에 맞는 분위기(테마·소품)를 고를 수 있게 하고, 검은 배경이 보이던 로비를 밝은 현대 미술관 로비로 바꿨습니다. 휴대폰에서 방을 옮길 때 끊기던 문제도 함께 해결했습니다.

3. 주요 기능

감상(학생·학부모)

  • 로그인 없이 입장, QR코드·공유 링크(?t=교사코드)로 해당 교사의 현재 전시 관람
  • 1인칭 이동: PC는 WASD + 방향키 + 마우스 클릭, 모바일은 자체 구현 조이스틱 + 드래그 + 탭
  • 로비 → A동 전시실들 → 연결 통로 → B동 전시실들 → 로비로 돌아오는 순환(ㅁ자) 동선
  • [Phase 9] 밝은 화이트 로비: 통유리벽 너머 낮 정원(하늘·잔디·돌길·나무), 테라초 바닥, 천장 선 조명, 창가 벤치·화분
  • [Phase 8] 전시실 테마 6종: 클래식(기본)·화이트 큐브·숲속 정원·바닷속·밤하늘·크레파스 놀이터. 테마마다 벽·바닥·천장 무늬, 액자, 강조색, 소품이 달라짐
  • 소품·벤치·화분에는 부딪힘 처리가 되어 있어 통과하지 않음
  • 작품 확대 보기, 좋아요(방문자 키로 중복 방지), 댓글(이름 10자·내용 80자)
  • 스마트폰 뒤로 가기 시 열린 창만 한 단계씩 닫힘

관리(교사)

  • 회원가입 → 관리자 승인 후 사용
  • 새 전시 만들기: 폴더/여러 장 업로드, 파일명(번호_이름_제목.jpg) 자동 해석, 방 자동 배정(방당 8점 기준 균등 분배), 진열 순서(이름순·랜덤·직접)
  • 기존 전시 관리: 정보 수정, 작품 수정·삭제·순서 변경, 작품 추가, 전시 삭제
  • [Phase 8] 전시실별 테마 선택 + 색 견본 + 소품 표시 켜기/끄기 (바꾸면 바로 저장)
  • 현재 전시장 설정: 교사마다 하나의 전시를 방문자에게 공개(is_active)
  • 관리자 화면 상단의 "우리 반 링크" 표시·복사 버튼
  • 댓글 숨김/복원, 감상 결과 리포트(오프라인 HTML 파일) 다운로드
  • 관리자 전용 교사 승인 탭
  • 시작·로그인 화면 "미술관 입장권" 디자인
  • 전시장 안 오른쪽 위 "↩ 처음 화면으로"(로그아웃 없이 업로드 관리자·QR 화면으로 복귀)와 로그아웃 버튼

4.2 파일 구조

(저장소 루트)
├── index.html              ← 화면 구조(HTML)만. CSS·JS를 불러옴
├── css/style.css           ← 모든 화면 디자인
├── js/                     ← 아래 순서대로 불러옴 (순서 변경 금지)
│   ├── auth.js             ← Supabase 연결, 로그인, 교사 승인 확인, QR코드
│   ├── demo-data.js        ← 데모(더미) 작품
│   ├── gallery-data.js     ← 전시·좋아요·댓글 불러오기 (전시실 theme·show_props 포함)
│   ├── themes.js           ← [Phase 8] 전시실 테마 정의·재질·캔버스 무늬·보조광
│   ├── props.js            ← [Phase 8] 테마별 소품, 소품 부딪힘 영역(PROP_OBSTACLES)
│   ├── scene.js            ← 3D 전시장 (로비·복도·전시실·조명 풀·작품 배치)
│   ├── lobby.js            ← [Phase 9] 로비 유리벽·바깥 정원·천장 선 조명·벤치와 화분
│   ├── controls.js         ← 이동, 벽·소품 충돌, 모바일 조이스틱
│   ├── viewer.js           ← 화면 갱신 루프, 시작 화면, 작품 창, 좋아요·댓글, 교사 버튼
│   ├── admin-upload.js     ← 새 전시 만들기, 교사 승인 탭
│   ├── admin-manage.js     ← 기존 전시 관리, 전시실 테마 설정, 작품 추가
│   └── report.js           ← 감상 결과 리포트
├── assets/                 ← 시작·로그인 화면 배경 (PC/모바일)
├── supabase/
│   ├── migrations/         ← 적용한 DB 변경 SQL (기록용)
│   └── rollback/           ← 되돌리기 SQL
├── docs/                   ← 개발 가이드(이 문서)
└── README.md               ← 배포 가이드
  • JS 파일은 모듈(import)이 아닌 일반 <script>로 불러와 전역 변수를 함께 씁니다. themes.js·props.js는 scene.js가 쓰므로 그 앞에, lobby.js는 scene.js의 LOBBY·재질을 쓰므로 바로 뒤에 둡니다.
  • ?v=는 브라우저 캐시 방지용입니다. 현재 값 예: scene.js?v=20261024i, lobby.js?v=20261024e, viewer.js?v=20261024g, style.css?v=20261024g. 하루에 여러 번 배포하므로 날짜 뒤에 알파벳을 붙여 올립니다.
  • 코드 규모: JS 12개 약 3,900줄, CSS 540줄, HTML 335줄.

  • 전시실의 앞쪽 절반은 A동(나가는 길), 뒤쪽 절반은 B동(돌아오는 길)에 배정합니다. B동은 방 순서를 뒤집어 지어서, 연결 통로를 지나 로비 쪽으로 걸어오면 번호 순서대로 마주칩니다.

  • 예: 작품 22점 → 방 3개(8/7/7) → A동에 1·2관, B동에 3관.

증상원인해결

10. 보안·성능 고려사항

보안

  • anon key는 공개되어도 되는 키이며 보호는 RLS가 담당합니다. Service Role Key는 절대 코드에 넣지 않습니다.
  • Supabase Auth: 회원가입 허용(승인제), 이메일 인증 켬, Google 로그인 꺼짐(버튼 숨김).
  • 보안 진단 현황: 방문자용으로 의도적으로 공개한 SECURITY DEFINER 함수 경고 2건, 유출 비밀번호 차단 꺼짐 경고 1건.
  • Phase 8의 rooms.theme은 체크 제약으로 6개 값만 허용 — 잘못된 값이 저장되지 않음. 앱도 모르는 키는 클래식으로 처리.

성능 (3D)

  • 조명 개수는 처음 한 번 정한 뒤 바꾸지 않습니다. 조명을 추가·삭제하거나 그림자 켜기/끄기를 바꾸면 셰이더 재컴파일로 멈춤이 생깁니다. 새 장식은 발광 재질이나 MeshBasicMaterial로 밝기를 냅니다.
  • 그림자는 현재 방 작품 조명만(그림자맵 768). 가까운 방(2칸 이내)만 조명을 배치.
  • 테마 재질은 테마별로 한 번만 만들어 재사용. 무늬 텍스처는 256~512px 캔버스(로비 하늘 1024×512, 나무 띠 2048×384).
  • 충돌 검사는 프레임당 사각형 십여 개 × 4점 비교로 부담이 거의 없음.

11.2 수동 테스트 체크리스트 (누적)

  1. 관리자 페이지에서 사진 15장 이상 업로드 → 전시실 3~4개 생성
  2. 로비 왼쪽 문으로 들어가 순서대로 관람, 어디서도 막히지 않는지(특히 연결 통로 앞뒤)
  3. 연결 통로를 지나 반대쪽 동 → 로비 오른쪽 문으로 복귀
  4. 로비 환영 사인에 실제 학년/반, 문틀 떨림 없음, 방마다 다른 색 띠
  5. 작품 8개 이하(전시실 1개)에서도 정상 동작
  6. 시작 화면 QR, 다른 기기로 스캔, "링크 복사"
  7. 모바일: 조이스틱·드래그·탭·첫 입장 안내 카드
  8. 감상 결과 리포트를 인터넷을 끄고 열어도 동작
  9. 새 계정 가입 → 승인 대기 → 관리자 승인 → 관리자 버튼 표시
  10. 교사 A의 전시가 교사 B 목록에 안 보임, 교사 링크 ?t=내코드로 내 현재 전시가 열림
  11. 좋아요 누르기·취소, 새로고침 후 유지 / 로그아웃 후 로그인 화면
  12. 벽·연결 통로 가운데 벽에 부딪히면 멈추고 비스듬히 부딪히면 미끄러짐
  13. [Phase 8] 관리 화면에서 전시실 테마를 바꾸면 바로 저장되고, 전시장에 들어가면 그 방의 벽·바닥·액자·소품이 바뀌는지
  14. [Phase 8] "소품 표시"를 끄면 그 방의 소품이 사라지는지, 소품에 부딪히면 멈추는지
  15. [Phase 8] 테마가 다른 방이 여러 개일 때 휴대폰에서 방을 옮겨도 끊김이 없는지
  16. [교사 버튼] 전시장 안 "↩ 처음 화면으로" → 로그아웃 없이 시작 화면, 방문자에게는 버튼이 안 보임
  17. [Phase 9] 로비에서 뒤를 돌아보면 유리벽 너머 정원이 보이고 검은 화면이 없는지, 벤치·화분에 부딪히면 멈추는지

    • 수업이 없는 시간에 SQL 적용과 앱 push를 한 번에

13. 알려진 한계

  • 교사마다 방문자에게 공개되는 전시는 하나입니다.
  • 현재 전시는 공개용이라, API를 직접 다루는 사람은 다른 반의 현재 전시를 조회할 수 있습니다(지난 전시는 불가).
  • 좋아요 중복 방지는 브라우저 기준입니다.
  • 댓글 부적절어 필터가 없습니다(사용자 결정으로 보류).
  • 진열 순서를 created_at에 의존합니다.
  • JS 파일이 전역 변수를 공유하므로 불러오는 순서에 의존합니다.
  • 조명 개수를 늘리는 장식은 넣기 어렵습니다. 새 장식의 밝기는 발광 재질로만 표현해야 멈춤이 생기지 않습니다.
  • 테마를 추가하려면 코드(themes.js, props.js)와 DB 체크 제약을 함께 바꿔야 합니다.
  • 로비 유리문은 장식입니다. 열리거나 밖으로 나갈 수 없습니다. 바깥 정원은 그림이라 가까이서 보면 평면적입니다.
  • 작품 사진이 큰 편(약 1500×2000)이라, 휴대폰에서 처음 들어갈 때 이미지를 받는 동안 잠깐 버벅일 수 있습니다(방 이동 멈춤과는 별개).
  • 발표용 테스트 계정의 복사본 전시는 원본과 이미지 파일을 공유합니다.
  • 로그인 후 처음 들어올 때 한 번 새로고침될 수 있습니다. favicon.ico가 없어 콘솔에 404가 하나 남습니다.
