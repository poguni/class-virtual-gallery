- 작성일: 2026-10-25

## 0. 새 대화창에서 작업을 이어가는 방법

1. 저장소를 내려받아 그 폴더에서 작업합니다: `git clone https://github.com/poguni/class-virtual-gallery.git`
2. 이 문서(`docs/Development_Guide_v10.md` 또는 `.html`)를 먼저 읽게 합니다.
3. 요청 예시:

> "docs/Development_Guide_v10.md를 참고해서 이어서 개발해줘. 다음 작업은 ◯◯이야."

- 코드는 **여러 파일로 나뉘어 있으므로**(4.2절) 고칠 기능에 해당하는 파일만 보면 됩니다.
- DB를 바꾸는 작업이면 `supabase/migrations/`에 SQL을 남기고, 되돌리기 SQL도 `supabase/rollback/`에 함께 둡니다(12절의 절차 참고).
- 3D 화면을 바꾸는 작업이면 **조명 개수를 늘리지 않는 것**이 원칙입니다(8절·10절). 새 장식의 밝기는 발광(emissive) 재질이나 조명 영향을 받지 않는 재질로 냅니다.
- 다음 큰 작업 후보인 **"여러 반 전시 동시 공개"의 설계안**은 14절에 정리해 두었습니다.

## 2. 목표 및 배경

- 미술 시간에 완성한 작품을 교실 벽에만 걸어두지 않고, **언제 어디서나 들어가 볼 수 있는 전시관**으로 만들어 주기 위해 시작했습니다.
- 교사는 사진 파일을 한 번에 올리기만 하면 되고(파일명으로 이름·제목 자동 입력, 전시실 자동 배정), 학생·학부모는 **QR코드 하나로** 바로 입장합니다.
- 감상 활동(좋아요·댓글)을 교사가 **감상 결과 리포트**로 내려받아 평가 자료로 활용할 수 있습니다.
- Phase 7은 여러 선생님이 함께 쓰기 위한 **보안·교사별 전시 분리**, Phase 8~9는 **"진짜 미술관에 온 느낌"**(전시실 테마·밝은 로비)이 목표였습니다.
- Phase 10은 **쓰기 편하고 안전하게**가 목표였습니다. 전시를 만들 때부터 테마를 고르게 하고, 고를 수 있는 테마를 늘리고, 로비 창밖이 계절·시간에 따라 달라지게 했습니다. 학생들이 쓰는 공간이므로 **댓글 욕설을 DB에서 막는 필터**도 더했습니다.

## 3. 주요 기능

**감상(학생·학부모)**
- 로그인 없이 입장, QR코드·공유 링크(`?t=교사코드`)로 해당 교사의 현재 전시 관람
- 1인칭 이동: PC는 WASD + 방향키 + 마우스 클릭, 모바일은 자체 구현 조이스틱 + 드래그 + 탭
- 로비 → A동 전시실들 → 연결 통로 → B동 전시실들 → 로비로 돌아오는 순환(ㅁ자) 동선
- 밝은 화이트 로비: 통유리벽 너머 정원, 테라초 바닥, 천장 선 조명, 창가 벤치·화분
- **[Phase 10] 로비 창밖 풍경이 계절(봄 꽃·여름 녹음·가을 단풍·겨울 눈)과 시간대(낮·노을·밤하늘)에 따라 바뀜**
- **전시실 테마 9종**: 클래식(기본)·화이트 큐브·숲속 정원·바닷속·밤하늘·크레파스 놀이터 + **[Phase 10] 우주정거장·눈 내린 겨울·한옥**. 테마마다 벽·바닥·천장 무늬, 액자, 강조색, 소품이 달라짐
- 소품·벤치·화분에는 부딪힘 처리
- 작품 확대 보기, 좋아요(방문자 키로 중복 방지), 댓글(이름 10자·내용 80자)
- **[Phase 10] 댓글 부적절어 필터**: 욕설·비속어가 들어간 이름·댓글은 저장되지 않고 "바르고 고운 말로 다시 써 주세요" 안내
- 스마트폰 뒤로 가기 시 열린 창만 한 단계씩 닫힘

**관리(교사)**
- 회원가입 → **관리자 승인** 후 사용
- 저장된 로그인 정보로 다시 들어올 때 입력 칸 대신 "저장된 로그인 정보로 들어가는 중이에요…" 안내 (v9 이후 개선)
- 새 전시 만들기: 폴더/여러 장 업로드, 파일명(`번호_이름_제목.jpg`) 자동 해석, 방 자동 배정(방당 8점 기준 균등 분배), 진열 순서(이름순·랜덤·직접)
- **[Phase 10] 새 전시 만들 때 전시실마다 테마·소품 표시 고르기**, 전시실 2개 이상이면 "모든 전시실 한 번에"
- 기존 전시 관리: 정보 수정, 작품 수정·삭제·순서 변경, 작품 추가, 전시 삭제, 전시실별 테마 변경(바꾸면 바로 저장)
- **현재 전시장 설정**: 교사마다 하나의 전시를 방문자에게 공개(`is_active`)
- 관리자 화면 상단의 "우리 반 링크" 표시·복사
- 댓글 숨김/복원, 감상 결과 리포트(오프라인 HTML 파일) 다운로드
- 관리자 전용 교사 승인 탭
- 시작·로그인 화면 "미술관 입장권" 디자인
- 전시장 안 오른쪽 위 "↩ 처음 화면으로"(로그아웃 없이 시작 화면으로)와 로그아웃 버튼

## 4. 기술 스택 및 아키텍처

### 4.1 구성 요소

| 영역 | 사용 기술 | 선택 이유 |
|---|---|---|
| 화면·3D | Vanilla JS + Three.js r128 (cdnjs) | 빌드 없이 파일만 올리면 동작, 교사가 직접 관리하기 쉬움 |
| 질감·무늬·풍경 | Canvas 2D로 그린 텍스처 | 이미지 파일을 따로 두지 않아 저장소가 가볍고, 색·무늬를 코드로 조정 가능 |
| 백엔드 | Supabase (Auth · Postgres · Storage) | 서버 없이 로그인·DB·이미지 저장을 한 번에 해결, RLS로 권한 제어 |
| 댓글 필터 | Postgres 트리거 + private 스키마 표 | 앱을 거치지 않는 직접 호출까지 막을 수 있음 |
| QR | qrcodejs 1.0.0 (cdnjs) | 접속 주소를 그 자리에서 QR로 그림 |
| 배포 | GitHub Pages (`main` 브랜치 루트) | 무료, push만 하면 1~2분 안에 자동 배포 |

### 4.2 파일 구조

```
(저장소 루트)
├── index.html              ← 화면 구조(HTML)만. CSS·JS를 불러옴
├── css/style.css           ← 모든 화면 디자인
├── js/                     ← 아래 순서대로 불러옴 (순서 변경 금지)
│   ├── auth.js             ← Supabase 연결, 로그인(저장된 세션 확인 중 안내), 교사 승인 확인, QR코드
│   ├── demo-data.js        ← 데모(더미) 작품
│   ├── gallery-data.js     ← 전시·좋아요·댓글 불러오기 (전시실 theme·show_props 포함)
│   ├── themes.js           ← 전시실 테마 9종 정의·재질·캔버스 무늬·보조광
│   ├── props.js            ← 테마별 소품, 소품 부딪힘 영역(PROP_OBSTACLES)
│   ├── scene.js            ← 3D 전시장 (로비·복도·전시실·조명 풀·작품 배치)
│   ├── lobby.js            ← 로비 유리벽·바깥 정원(계절·시간대)·천장 선 조명·벤치와 화분
│   ├── controls.js         ← 이동, 벽·소품 충돌, 모바일 조이스틱
│   ├── viewer.js           ← 화면 갱신 루프, 시작 화면, 작품 창, 좋아요·댓글(필터 안내), 교사 버튼
│   ├── admin-upload.js     ← 새 전시 만들기(전시실별 테마), 테마 고르기 공용 칸, 교사 승인 탭
│   ├── admin-manage.js     ← 기존 전시 관리, 전시실 테마 변경, 작품 추가
│   └── report.js           ← 감상 결과 리포트
├── assets/                 ← 시작·로그인 화면 배경 (PC/모바일)
├── supabase/
│   ├── migrations/         ← 적용한 DB 변경 SQL (기록용)
│   └── rollback/           ← 되돌리기 SQL
├── docs/                   ← 개발 가이드(이 문서)
└── README.md               ← 배포 가이드
```

- JS 파일은 모듈(`import`)이 아닌 **일반 `<script>`**로 불러와 전역 변수를 함께 씁니다. `themes.js`·`props.js`는 `scene.js`가 쓰므로 그 앞에, `lobby.js`는 `scene.js`의 `LOBBY`·재질을 쓰므로 **바로 뒤에** 둡니다.
- `?v=`는 브라우저 캐시 방지용입니다. 현재 값: `style.css?v=20261025b`, `auth.js`·`themes.js`·`props.js`·`lobby.js`·`viewer.js`·`admin-upload.js`·`admin-manage.js`는 `?v=20261025a`, 나머지는 `20261024…`. 하루에 여러 번 배포하므로 날짜 뒤에 알파벳을 붙여 올립니다.
- 코드 규모: JS 12개 약 4,300줄, CSS 548줄, HTML 339줄.

### 4.3 DB 구조 (Supabase 프로젝트 `xloetjawdupadtfquxka`)

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `teachers` | `user_id`, `email`, `status`(pending/approved/rejected), `is_admin`, `share_code`, `approved_at` | 회원가입 시 트리거가 `pending`으로 자동 등록 |
| `exhibitions` | `id`, `title`, `grade`, `class`, `created_at`, `owner_id`, `is_active` | 교사별 현재 전시는 하나(부분 유니크 인덱스) |
| `rooms` | `id`, `exhibition_id`, `room_number`, `name`, `theme`, `show_props` | `theme` 기본 `classic`, **9종만 허용**(체크 제약), `show_props` 기본 켬 |
| `artworks` | `id`, `room_id`, `student_name`, `title`, `image_url`, `created_at` | 진열 순서 = `created_at` 순 |
| `likes` | `artwork_id`, `visitor_key`, `created_at` | `(artwork_id, visitor_key)` 유니크 |
| `comments` | `artwork_id`, `nickname`, `content`, `is_hidden`, `created_at` | 이름 1~10자, 내용 1~80자 DB 제약 + **부적절어 트리거** |
| `private.banned_words` (Phase 10) | `word`, `note` | 금지어 53개. API로 노출되지 않음 |
| `private.allowed_words` (Phase 10) | `word`, `note` | 예외 단어 5개(시발점·시발역·졸라맨·졸라매·등신대) |

- `rooms.theme` 허용 값: `classic`, `whitecube`, `forest`, `ocean`, `night`, `crayon`, `space`, `winter`, `hanok` — `js/themes.js`의 `ROOM_THEMES` 키와 **같아야 합니다.** 테마를 추가하려면 두 곳을 함께 고칩니다.
- Storage 버킷 `artwork-images`(public): 경로 `전시ID/전시실ID/파일명`, 10MB 이하·jpeg/png/webp/gif만 허용.
- DB 함수(RPC): `get_active_exhibition(p_code)`, `like_counts(p_artwork_ids)`, `set_active_exhibition(p_ex)`.
- 정책 판단용 헬퍼(`private` 스키마): `is_approved_teacher`, `is_admin`, `can_manage_exhibition`, `is_public_exhibition`, `room_exhibition`, `artwork_exhibition`, `can_manage_storage_path`, `request_visitor_key`.
- 댓글 필터(`private` 스키마, Phase 10): `normalize_comment_text(t)`(띄어쓰기·숫자·특수문자 제거, 영어 소문자), `has_banned_word(t)`(예외 단어를 먼저 지운 뒤 금지어 포함 여부), `check_comment_words()` + 트리거 `comments_word_filter`(댓글 등록, 이름·내용 수정 직전).

### 4.4 권한 모델 (RLS)

| 대상 | 방문자(비로그인) | 승인 대기 교사 | 승인 교사 | 관리자 |
|---|---|---|---|---|
| 현재 전시(`is_active`) 조회 | ✅ | ✅ | ✅ | ✅ |
| 지난 전시 조회 | ❌ | ❌ | 내 것만 | 내 것만 |
| 전시·전시실(테마 포함)·작품·이미지 생성/수정/삭제 | ❌ | ❌ | 내 것만 | 내 것만 |
| 댓글 등록 (부적절어는 누구든 거절) | 공개 전시에 | 공개 전시에 | ✅ | ✅ |
| 숨긴 댓글 조회·댓글 숨김/삭제 | ❌ | ❌ | 내 전시만 | 내 전시만 |
| 좋아요 조회·취소 | 내 방문자 키만 | 〃 | 내 전시 전체 조회 | 〃 |
| 교사 승인/거절 | ❌ | ❌ | ❌ | ✅ |
| 금지어 목록 읽기·수정 | ❌ | ❌ | ❌ | ❌ (DB 관리 화면·SQL로만) |

- 방문자 키는 브라우저 `localStorage`에 만들고, 모든 요청에 **`x-visitor-key` 헤더**로 보냅니다.
- 관리자는 승인만 담당하며 **다른 교사의 전시는 관리자도 볼 수 없습니다.**
- Phase 10의 변경(테마 허용 값 추가, 댓글 트리거)은 **권한 정책을 바꾸지 않았습니다.**

## 6. 전체 공간(동선) 구조

```
          (바깥 정원: 하늘·잔디·돌길·나무 띠 — 계절·시간대에 따라 색이 바뀜)
                 ═══════════════   ← 통유리벽 + 유리문
                 │ 벤치    벤치 │  화분은 양 모서리
                 │     로비      │  (환영 사인: 실제 전시 학년/반 표시)
                 │  A동문   B동문 │
                 └──┬─────────┬──┘
                    │         │
              [A동 복도]   [B동 복도]
                    │         │
              [제1전시실]  [제N전시실]  (B동은 방 번호를 뒤집어서 지음)
                    │         │
                    …         …
                    │         │
              [제k전시실]  [제k+1전시실]
                    │         │
                    └────┬────┘
                   [연결 통로(가로)]  ← 두 동의 가장 안쪽 끝을 이어붙임
```

- 전시실의 앞쪽 절반은 A동(나가는 길), 뒤쪽 절반은 B동(돌아오는 길)에 배정합니다. B동은 방 순서를 뒤집어 지어서, 연결 통로를 지나 로비 쪽으로 걸어오면 번호 순서대로 마주칩니다.
- 로비 입구 쪽(`LOBBY.maxZ`)은 유리벽입니다(걸어 나갈 수는 없음).
- 예: 작품 22점 → 방 3개(8/7/7) → A동에 1·2관, B동에 3관.

## 8. 주요 의사결정과 이유

| 결정 | 이유 |
|---|---|
| 회원가입 즉시 교사 → **관리자 승인제** | 가입이 열려 있어 학생이 아무 이메일로 가입해 전시 전체를 지울 수 있었음 |
| 전시에 `owner_id`, 교사별 `is_active` 하나, 공유 링크는 교사 코드(`?t=`) | 다른 교사의 전시 분리 + 현재 전시를 바꿔도 인쇄한 QR을 계속 사용 |
| 정책 헬퍼를 `private` 스키마에, 좋아요는 헤더 + `like_counts()` | 공격 면 축소, 비로그인 방문자 구분 |
| 파일 분리는 모듈화 없이 "잘라서 옮기기" | 빌드 도구 없이 GitHub Pages 배포 방식을 그대로 유지 |
| 테마는 전시실 단위, 기존 전시실은 `classic` 기본값 | 방마다 주제를 달리할 수 있고, 마이그레이션만으로는 어떤 전시도 바뀌지 않음 |
| 조명을 지웠다 만들지 않고 "조명 풀"에서 옮기기 | 조명 개수가 바뀌면 셰이더 재컴파일로 휴대폰에서 1~3초 멈춤 |
| 로비는 "유리벽 + 바깥 정원", 밝기는 발광 재질로 | 검은 배경을 가리면서 개방감, 조명 수 유지 |
| **자동 로그인 시 입력 칸 대신 안내 문구** | 저장된 세션 확인과 전시장 준비가 겹쳐 입력이 안 되다가 갑자기 넘어가는 것이 어색함. 자동 로그인 자체는 편리하므로 유지하고 보여주는 방식만 바꿈 |
| **세션 확인 여부를 `localStorage` 키로 바로 판단** | 비동기 확인(`getSession`)을 기다리면 입력 칸이 한 순간 깜박임. 페이지를 그릴 때부터 상태를 정함 |
| **[10-1] 테마 고르는 칸을 공용 함수로** | 새 전시 만들기와 기존 전시 관리의 모양·동작을 같게, 10-2에서 테마를 추가하면 두 화면에 저절로 나타남 |
| **[10-1] 새 전시실은 앞 방의 테마를 이어받음** | "모든 전시실 한 번에"로 고른 뒤 사진을 더 넣어 방이 늘어도 같은 테마가 유지됨 |

| **[10-4] 띄어쓰기·숫자·특수문자 제거 후 비교 + 예외 목록** | "시 발", "시1발" 같은 우회를 막고, "시발점·졸라맨"처럼 정상 낱말은 통과 |
| **[10-4] 흔히 정상으로 쓰는 말은 목록에서 뺌** | "새끼 고양이", "불이 꺼져서", "시바견", "꿈을 좇는", "쓰레기 분리수거" 등 오탐 방지 |

## 10. 보안·성능 고려사항

**보안**
- **anon key**는 공개되어도 되는 키이며 보호는 RLS가 담당합니다. Service Role Key는 절대 코드에 넣지 않습니다.
- **Supabase Auth**: 회원가입 허용(승인제), 이메일 인증 켬, Google 로그인 꺼짐(버튼 숨김).
- **보안 진단 현황**(Phase 10 적용 후 재확인, 새 경고 없음): 방문자용으로 의도적으로 공개한 SECURITY DEFINER 함수 경고 2건(`get_active_exhibition`, `like_counts`), 유출 비밀번호 차단 꺼짐 경고 1건.
- `rooms.theme`은 체크 제약으로 9개 값만 허용. 앱도 모르는 키는 클래식으로 처리.
- **댓글 필터**: 트리거 함수는 `security definer` + `search_path = ''`. 금지어·예외 표와 필터 함수는 `public`·`anon`·`authenticated` 권한을 모두 회수해 방문자가 목록을 읽거나 함수를 직접 부를 수 없음(적용 후 `anon` 읽기 권한 없음 확인).
- 저장된 로그인 확인 중 안내는 화면 표시만 바꾼 것이며, 실제 권한 판단(승인 상태 확인)은 그대로 `enterWithSession`이 함.

**성능 (3D)**
- **조명 개수는 처음 한 번 정한 뒤 바꾸지 않습니다.** 새 장식은 발광 재질이나 `MeshBasicMaterial`로 밝기를 냅니다.
- 그림자는 현재 방 작품 조명만(그림자맵 768). 가까운 방(2칸 이내)만 조명을 배치.
- 테마 재질은 테마별로 한 번만 만들어 재사용. 무늬 텍스처는 256~512px 캔버스(로비 하늘 1024×512, 나무 띠 2048×384).
- 로비 풍경은 페이지를 열 때 한 번만 그림. 계절·시간대 12가지 모두 셰이더 수가 변경 전과 같음(16개).
- 댓글 필터는 댓글 1건 저장 시 금지어 53개·예외 5개 문자열 비교뿐이라 부담이 거의 없음.

## 11. 테스트 및 검증

### 11.1 v9 이후(Phase 10)에 수행한 검증

DB를 건드리는 검사는 **끝에서 일부러 오류를 내 전부 되돌리는 시험 실행**으로 하고, 실행 뒤 아무것도 남지 않았는지 다시 확인했습니다. 화면 검사는 Playwright로 하며, 실제 DB에 저장하지 않도록 서버 응답을 가로채 흉내 냈습니다.

### 11.2 수동 테스트 체크리스트 (누적)

1. 관리자 페이지에서 사진 15장 이상 업로드 → 전시실 3~4개 생성

6. 시작 화면 QR, 다른 기기로 스캔, "링크 복사"
7. 모바일: 조이스틱·드래그·탭·첫 입장 안내 카드
8. 감상 결과 리포트를 **인터넷을 끄고** 열어도 동작
9. 새 계정 가입 → 승인 대기 → 관리자 승인 → 관리자 버튼 표시
10. 교사 A의 전시가 교사 B 목록에 안 보임, 교사 링크 `?t=내코드`로 내 현재 전시가 열림
11. 좋아요 누르기·취소, 새로고침 후 유지 / 로그아웃 후 로그인 화면

- **주소**: https://poguni.github.io/class-virtual-gallery/ (교사별 링크: `…/?t=교사코드`)

  3. 사용자 확인 후, 수업이 없는 시간에 **SQL 적용과 앱 push를 한 번에**(새 코드가 새 DB 값을 쓰는 경우 순서가 어긋나면 잠시 저장 실패)
  4. 적용 결과 확인 + 보안 진단 재실행 + 배포 사이트 확인
- **Phase 10의 DB 변경**: `20261025_room_themes_more.sql`(테마 허용 값 9종), `20261025_comment_word_filter.sql`(금지어 표·필터 함수·트리거)
- **되돌리기**
  - 댓글 필터: `supabase/rollback/20261025_comment_word_filter_rollback.sql`(트리거·함수·목록 삭제, 댓글 데이터는 그대로) + `git revert db930c4`

## 13. 알려진 한계

- **교사마다 방문자에게 공개되는 전시는 하나**입니다(여러 반 동시 공개는 14절 설계안, 보류 중).
- **현재 전시는 공개용이라**, API를 직접 다루는 사람은 다른 반의 현재 전시를 조회할 수 있습니다(지난 전시는 불가).
- **좋아요 중복 방지는 브라우저 기준**입니다.
- **댓글 필터는 낱말 목록 방식**입니다.
  - 목록에 없는 새 욕설·은어, 글자를 바꿔 쓴 변형(예: 비슷한 모양의 다른 글자), 욕설 없이 하는 놀림·비꼼은 막지 못합니다. 이런 댓글은 교사가 숨김으로 대응합니다.
  - 띄어쓰기를 지우고 비교하므로, 두 낱말이 이어 붙어 우연히 금지어가 되는 정상 문장이 드물게 막힐 수 있습니다. 발견되면 예외 목록에 넣습니다.
  - 목록 관리는 현재 SQL로만 할 수 있습니다(관리 화면 없음).
  - **필터 적용 전에 달린 댓글은 그대로**입니다. 현재 '소인국 놀이터' 전시(원본과 test1 복사본)에 금지어가 든 댓글 1개씩이 숨김되지 않은 상태로 남아 있습니다.
- **로비 풍경은 보는 사람 기기의 날짜·시각 기준**입니다. 기기 시계가 틀리면 다른 계절·시간대가 보이고, 남반구·다른 시간대 기준은 고려하지 않습니다. 페이지를 연 채로 시간이 지나도 다시 열기 전까지는 바뀌지 않습니다.
- **진열 순서를 `created_at`에 의존**합니다.
- **JS 파일이 전역 변수를 공유**하므로 불러오는 순서에 의존합니다.
- **조명 개수를 늘리는 장식은 넣기 어렵습니다.**
- **테마를 추가하려면 코드(`themes.js`, `props.js`)와 DB 체크 제약을 함께 바꿔야** 합니다.
- **로비 유리문은 장식**이고 바깥 정원은 그림입니다.
- **작품 사진이 큰 편(약 1500×2000)**이라 휴대폰 첫 입장 때 잠깐 버벅일 수 있습니다.
- 발표용 테스트 계정의 복사본 전시는 원본과 이미지 파일을 공유합니다.
- `favicon.ico`가 없어 콘솔에 404가 하나 남습니다.

## 14. 향후 개선 아이디어 / 업데이트 계획

### 14.1 보류 중인 큰 작업: 교사 한 명이 여러 반 전시를 동시에 공개 (10-5)

사용자 결정으로 Phase 10에서 빼고 다음으로 미뤘습니다. DB와 권한 규칙을 크게 바꾸는 가장 위험한 작업이므로 아래 설계안을 바탕으로 진행합니다.

- **DB**
  - `exhibitions`에 전시별 공유 코드(`share_code`, 자동 생성)와 공개 여부(`is_public`)를 추가합니다.
  - 지금의 `is_active`는 **"대표 전시"**로 의미만 바꿔 유지합니다.
  - 마이그레이션 때 현재 `is_active`인 전시는 `is_public = true`로 옮깁니다.
- **링크 호환**
  - 이미 인쇄·공유한 교사 링크 `?t=교사코드`와 코드 없는 주소는 계속 대표 전시를 엽니다.
  - 새 링크 `?e=전시코드`는 그 전시가 공개일 때 엽니다.
- **권한**
  - `private.is_public_exhibition`을 "공개된 전시 전부"로 넓힙니다. 좋아요·댓글 권한이 이 함수를 따릅니다.
  - 새 RPC `get_public_exhibition(p_code)`를 추가합니다.
- **화면**
  - 기존 전시 관리에 전시별 공개 켜기/끄기, 링크 복사, QR 보기를 둡니다.
  - 교사 시작 화면에서 어느 전시를 볼지(어느 QR을 띄울지) 고르게 합니다.
  - `gallery-data.js`의 불러오기 순서에 `?e=`를 추가합니다.
- **절차**
  - 바꾸는 SQL과 되돌리기 SQL을 쓰고, 시험 실행으로 방문자·승인 대기 교사·교사 A/B·관리자의 권한을 검사합니다.
  - 수업 없는 시간에 SQL 적용과 앱 push를 한 번에 합니다.
  - 기존 QR·링크 3종(코드 없음, `?t=`, 잘못된 코드), 새 `?e=` 링크, 비공개 전환, 다른 교사의 비공개 전시가 안 보이는지 확인합니다.

### 14.2 다음에 하면 좋을 것
